- `init` 必须先读取并验证已有配置，再创建其他工作区资源；配置语法或结构无效时返回失败，保留已有文件且不新增工作区资源。
- 案件级阶段由 `orev.toml` 的 `stages` 统一驱动：`init` 仅为启用阶段创建 `stage.yaml`、`out/`、`log/` 三槽位且不删除已有成果，`doctor` 仅要求启用阶段存在。
- 固定案例的逻辑目录布局，删除 `[workspace]` 及其目录改名字段，使配置生成、初始化与体检采用同一套固定命名；物理存储位置通过后续独立的存储根配置表达，不保留旧字段兼容逻辑。
- 冷区由 `storage.store_root` 指定物理位置，省略时由 `init` 创建案内 `store/`，显式配置必须指向解析后位于案例之外的现存绝对目录，`init` 与 `doctor` 复用同一解析规则且不自动创建外置根、搬移数据或建立符号链接。
- 工具资产区由可选的 `storage.tools_root` 指定，省略时由 `init` 创建案内 `tools/`，显式配置沿用冷区的案外现存绝对目录规则，两类根由 `init` 与 `doctor` 共享解析并在创建子资源前完成验证，初始化不创建具体工具项目。
- 案件专用脚本统一归档于案内 `scripts/<tool>/` 并纳入 Git，`init` 仅准备 `scripts/` 根目录且保留已有内容，具体工具子目录按需建立、同名文件冲突明确报错，`doctor` 检查该根目录但不生成或执行脚本。
- 配置根及各配置表严格拒绝未知或尚未实现的字段，`init` 与 `doctor` 明确指出错误字段并以失败退出、保留已有文件且不新增工作区资源，文档同时区分当前可运行配置与扩展设计参考。
- `stages` 在配置反序列化时仅接受规范中的九个完整阶段名，区分大小写且不自动裁剪空白，非法名称由 `init` 与 `doctor` 在创建其他资源前拒绝，保留空列表和重复项的既有行为且不校验执行依赖或阶段完成状态。
- 已有配置中的 `case.name` 是初始化输出及新生成案件导引的唯一名称来源，显式 `--name` 与其冲突时在创建其他资源前失败且不改已有文件，新案件仍按显式名称、目录名、默认名称的优先级取名。
- 初始化文件在目标目录内完整写入并同步临时文件后以无覆盖方式发布，竞争创建时保留已有有效文件并以实际落盘配置为准，失败时尝试清理临时文件并明确报错，不承诺整案事务回滚或断电级持久性。
- 初始化的文件发布保证由模块内单元测试验证，命令行为由持久化 CLI 集成测试覆盖，重初始化须逐字节保留已有配置、导引、忽略规则、台账和阶段成果，合法符号链接保留而悬空或类型冲突明确失败。
