# 16. 落地检查清单

**开案时**

- [ ] 编写 `CASE.md`，用一句话说明要回答的问题
- [ ] 在 `orev.toml` 中声明 `stages` 启用列表
- [ ] 将 `00_inbox/` 设为只读；确认 `stage.yaml` 的 `input_file` 已填写实际文件名
- [ ] 填写 `provenance.json`，包含来源、授权与声明版本
- [ ] 生成 `checksums.sha256`，并通过 `sha256sum -c` 校验（[§5.2](../01-layout/04-阶段产物清单.md#52-00_inbox-两个元数据文件的职责边界)）
- [ ] 确认 target-id 只含「文件名_哈希」；确认架构、版本、格式已写入 `provenance.json` 与 `headers.json`，且未写入目录名（[§3.2](../01-layout/02-目标标识.md#32-四条硬规则) 第 2 条）
- [ ] 选定启用档位 D0 / D1 / D2（[§14](../00-overview/02-启用档位.md)）
- [ ] 主盘空间紧张时，在 `[storage]` 中声明 `tools_root` 与 `store_root`，指向大容量盘（[§2.1](../01-layout/01-顶层布局.md#21-冷区-store-与工具资产区-tools)）

**过程中**

- [ ] 为每个阶段目录建立 `stage.yaml`，并保证 `tool.cmd` 可原样重跑（**D0 档位可豁免**）
- [ ] 为产物记录添加 `tags`：多组件目标添加 `component=`，涉及线索的添加 `thread=TH<n>`
- [ ] 开设新线索时，向 `investigation.jsonl` 登记并填写 `question`
- [ ] 关键阶段进入 `status: ok` 后打 git tag（[§11](../02-workflow/04-时间旅行与版本控制.md)）
- [ ] 确认工具自检通过后才标记 `ok`：`tool.selfcheck.analyzed` 为 `true`，且未发生超时截断（[§17.2](../04-appendix/02-Ghidra-12.1.4-对照.md#172-30_decompile-的两种执行方式)）

**收尾前**

- [ ] 确认 `findings.jsonl` 每条都有 `evidence[]` 与 `limitations`（**`limitations` 为空即不合规**）
- [ ] 确认 `confidence` 落在 `status` 对应的区间内（[§6.4](../02-workflow/01-证据契约.md#64-status-与-confidence-的区间约束)）
- [ ] 确认每条 evidence 的 `type` 在受控词表内（[§6.3](../02-workflow/01-证据契约.md#63-evidencetype-受控词表吸收-reark)）
- [ ] 处理全部 `assumed` 级结论：补充证据升级，或写入 `gaps.md`
- [ ] 确认动态产物已备份
- [ ] 确认工具项目文件已备份
- [ ] 存在第二个版本的目标时，在 `[[diff]]` 中声明两端与 `name`，并执行 `60_diff`
- [ ] 将本次遇到的新问题写入 `kb/pitfalls/`
- [ ] 生成 `manifest.json`，并记录 permanent 产物的校验和
- [ ] 确认 `sample/` 权限为 `700`
- [ ] 确认 `signing_material` 未泄露密钥
- [ ] 将 `.cache/`、`store/`、`tools/*/working/`、`state/env.md` 加入备份排除与 git 排除列表（`scripts/` 除外，必须入库）
- [ ] 关闭工具项目后再执行备份，并保证 `.gpr` 与 `.rep/` 成对拷贝（[§8.1](../03-operations/01-保留分级与清理.md#81-保留分级)）
- [ ] 对备份后的 Ghidra 项目执行一次换路径打开验证（**字节未变不等于数据库未损坏**）
- [ ] 使用 BSim 时，在 `corpus/bsim/README.md` 中记录构建命令与 Ghidra 版本（[§10](../02-workflow/03-知识库与语料库.md)）
- [ ] 使用 Ghidra 执行版本对比时，在 `60_diff/out/<diff-name>/vtsession.json` 中记录 correlator 组合与 markup 应用情况（[§17.3](../04-appendix/02-Ghidra-12.1.4-对照.md#173-60_diff--version-tracking)）
- [ ] 将工具工作区单独纳入备份任务（它不在主树中，主树备份覆盖不到）
- [ ] 确认未使用符号链接代替移动（[§8.1.1](../03-operations/01-保留分级与清理.md#811-required-备份纪律)）
- [ ] 确认工具工作区位于 `tools/<tool>/working/<case-id>/…`
- [ ] 在 `stage.yaml` 中填写 `tool.project_dir`（[§2.1](../01-layout/01-顶层布局.md#21-冷区-store-与工具资产区-tools)）
- [ ] 将案件专用脚本放入 `cases/<case-id>/scripts/<tool>/`
- [ ] 将跨案件脚本放入 `tools/<tool>/scripts/`，并注明适用工具版本（[§2.1](../01-layout/01-顶层布局.md#21-冷区-store-与工具资产区-tools)）
