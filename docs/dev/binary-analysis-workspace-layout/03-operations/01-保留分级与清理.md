# 8. 保留分级、清理与完整性

## 8.1 保留分级

> 四个级别使用**语义词**而非编号。这些值会写入 `index.jsonl` 与 `stage.yaml` 的 `retention` 字段，必须脱离本规范也能读懂。记号治理原则见 [§0](../00-overview/00-编号体系速查.md)。

| 级别 | 含义 | 位置 | 清理 | 备份 | **进 git** |
| --------------- | ----------------- | ------------------------------------------------------------------ | -------- | -- | ----------- |
| **permanent** | 永久：输入与结论 | `00_inbox/`、`50_findings/`、`60_diff/`、`90_report/`、`kb/`、`corpus/` | 永不 | 必须 | ✅ |
| **required** | 必须保留：含人工认知 / 不可再生 | **`tools/<tool>/working/`**、`40_dynamic/` | 仅手动确认 | 必须 | **❌ 仅索引条目** |
| **rebuildable** | 可再生但昂贵 | `10_unpack/`、`15_patch/`、`20_static/`、`30_decompile/out/` | 结项 90 天后 | 可选 | ❌ |
| **temp** | 临时 | `.cache/`、`log/`、`state/env.md` | 随时 | 否 | ❌ |

> **澄清**：「required 元数据进 git」的说法不正确。`.gitignore` 已忽略 `.gpr`、`.rep`、`.i64`、`.bndb`。准确说法是：**进 git 的是 `index.jsonl` 中描述该产物的索引条目**，包括路径、哈希、大小与保留级别。工具项目文件本身走备份，不走 git。

## 8.1.1 required 备份纪律

工具数据库不是普通文件。**直接执行 `cp` 可能得到无法打开的副本**：

| 工具 | 备份单元 | 前置条件 |
| ------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Ghidra** | `.gpr` **+ 同名 `.rep/` 目录**（二者缺一不可） | **必须先在 Ghidra 中关闭项目**，否则 `~index.dat` / `~journal.dat` 可能未落盘 |
| IDA | 单个 `.i64` | 关闭 IDA |
| Binary Ninja | 单个 `.bndb` | 关闭 BN |
| radare2 | 项目目录（含 `.git`） | 关闭 r2 |
| **rizin** | 单个 `.rzdb`（SDB 格式，自带格式版本号） | 关闭 rizin。⚠️ **跨版本加载会自动迁移格式**（v0.9 起最低项目版本 25），**迁移是单向的**——老版本工具读不回新格式。要保留回滚能力，请**保留旧 `.rzdb` 副本**（带日期后缀），不要只依赖迁移 |

**规则**：

1. **整包拷贝，不要逐个挑文件**。Ghidra 的 `.rep/` 中，`project.prp`、`idata/`、`versioned/`、`user/`、`~*.db` 相互引用，构成一个整体。
2. **先关闭项目，再执行拷贝**。依据 Ghidra 官方说明：索引文件损坏后可以重建，但**必须在项目关闭或 Ghidra Server 停止**的前提下操作。在项目打开状态下拷贝，副本可能不完整。
3. **拷贝后必须验证可打开**。验证备份有效性只有一种方式：换一个路径，用工具打开一次。`orev verify --check` 只能证明字节未变，不能证明数据库未损坏。
4. **`.rep/` 是目录**，`.gitignore` 中写 `*.rep/`（带斜杠）。
5. **不要用符号链接代替移动**。工具项目处于活动状态，工具会读写、加锁并写日志。让工具直接写入目标路径（见 [§2.1](../01-layout/01-顶层布局.md#21-冷区-store-与工具资产区-tools) 的 `tools_root`）优于给工具一个符号链接。备份脚本默认使用 `rsync -a`，该命令保留符号链接本身而不跟随链接，拷出的内容会是空壳。这类文件恰恰是不能丢失的 `required` 级产物。
6. **工具工作区必须单独备份**。它不在主树中，主树的备份任务覆盖不到它。备份脚本必须纳入 `tools_root` 与 `store_root`。其中 `tools/*/working/` 必须遵守上述第 1 至 3 条；冷区可直接 `rsync`；`tools/*/scripts/` 与 `extensions/` 是文本或普通文件，随 git 或常规备份即可。

## 8.2 `.gitignore`

模板见 [`schemas/workspace.gitignore`](../schemas/workspace.gitignore)。使用时复制到工作区根目录，并改名为 `.gitignore`。

要点：一行只写一个 pattern，空格分隔的写法不生效；目录 pattern 必须带尾斜杠；`tools/*/working/` 与 `store/` 走备份，不走 git。`00_inbox` 采用**先全忽略再用 `!` 放行元数据**的写法 —— 样本文件名不固定（[§5.2](../01-layout/04-阶段产物清单.md#52-00_inbox-两个元数据文件的职责边界)），无法按名字匹配。

产出 `state/checksums.jsonl`：

样例见 [`schemas/checksums.jsonl`](../schemas/checksums.jsonl)。每行一个 JSON 对象。

**规则**：permanent 产物每次分析前后各校验一次；发现不一致一律视为**安全事件**，不得静默覆盖。

## 8.4 清理前的安全检查

命令见 [`scripts/pre-clean-check.sh`](../scripts/pre-clean-check.sh)。

> 删除任何 required 或 rebuildable 目录前，必须同时满足三个条件：该目录的 `stage.yaml` 存在、`status: ok`、`tool.cmd` 完整。否则删除的内容无法重建。
> **S7 原子写**：产物一律先写入 `xxx.tmp`，再用 `mv` 改名为目标文件名。此做法避免执行中断产生的半截文件混入索引。
