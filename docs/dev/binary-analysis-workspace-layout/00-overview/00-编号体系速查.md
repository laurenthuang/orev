# 0. 编号体系速查 ★

本节集中登记文档中出现的全部记号。新增任何编号体系前，必须先在本节登记并查重。

## 0.1 前缀注册表

| 记号 | 全称 | 语义 | 会写进产物字段吗 | 数字方向 |
| --------------------------------------------- | ------- | ---------------- | ----------------------- | ----------- |
| **T1–T7** | Time | 时间维度**要求**（设计约束） | ❌ 仅正文论证 | 无强弱，纯序号 |
| **S1–S8** | Space | 空间维度**要求**（设计约束） | ❌ 仅正文论证 | 无强弱，纯序号 |
| **permanent / required / rebuildable / temp** | — | **保留级别**（能不能删） | ✅ `retention:` 字段 | 无编号，见 [§8.1](../03-operations/01-保留分级与清理.md#81-保留分级) |
| **D0–D2** | Depth | **启用档位**（这次做多深） | ⬜ 仅 `CASE.md` 与检查清单元数据 | **数字越大越完整** |
| **TH1, TH2…** | Thread | **调查线索**（纵轴） | ✅ `thread_id`、产物 `tags` | 无强弱，纯序号 |
| **F-001…** | Finding | 结论编号 | ✅ `claim_id` | 无强弱，纯序号 |
| **NN\_** | — | 阶段号（00–90） | ✅ `stage` 字段 | 数字越大越靠后 |

## 0.2 三条治理原则

1. **分层治理**。只用于正文论证的编号（T、S）可以使用单字母。写入产物字段的值必须自解释。
   > 原因：`retention: "required"` 半年后会单独出现在某个 `stage.yaml` 中。此时读者手上没有本规范。一个需要查对照表才能读懂的值，在该场合等于没有信息。
2. **显式声明方向**。等级类编号必须在本表中写明数字方向：D 的数值越大，分析深度越完整。不允许让读者自行猜测。
3. **规避流行语义**。单字母前缀在业界已有约定：P 表示 Priority，L 表示 Level，T 表示 Tier，S 表示 Service。凡会脱离本文档独立存在的值，一律不使用裸单字母。

> **编号与词表的分工**：有序且可比较的信息用编号，包括档位 D、线索 TH、结论 F、阶段号。无序且类别性的信息用词表，包括 `evidence[].type` 的 12 类与 `status` 的 4 个值。不要给词表编号。
