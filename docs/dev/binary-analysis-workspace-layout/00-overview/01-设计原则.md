# 1. 设计原则

## 1.1 双轴模型

本规范用两类正交的轴组织一次分析：

- **横轴：时间**。用目录名的编号前缀表达，包括阶段顺序、执行先后与可重放的流水线。
- **纵轴：线索**。用台账与标签表达，记录一次分析中并行推进的多条调查线。

空间不单列成轴。空间由阶段目录内的固定槽位名表达：`stage.yaml`、`out/`、`log/`。

分析过程通常不是从 `20_static` 顺序执行到 `30_decompile`。多条线索会并行推进，且每条线索都跨多个阶段。典型路径如下：

```
概览 → 字符串 → 交叉引用 → 调用图 → 伪代码 → 运行时验证
```

**纵轴不建目录，只用标签关联。** 线索天然跨阶段。为线索建目录会重复文件或产生大量符号链接。本规范改用两处轻量记录：

- `state/investigation.jsonl`：线索台账
- 产物 `tags` 字段：`thread=TH2` 表示关联到 TH2 号线索

这两处记录不增加目录数量，且支持双向查询。

## 1.2 时间维度要求（T1–T7）

| 编号 | 要求 | 说明 |
| ------ | -------------- | ------------------------------------------------ |
| **T1** | 阶段有序、可编排 | 编号可排序，脚本可枚举。参考 EMBA 的 `p02_` / `s06_` / `f50_` 前缀 |
| **T2** | 可复现与溯源 | 记录执行人、工具版本、参数、输入、时间与耗时 |
| **T3** | 区分「一次性」与「每次都要」 | 语料库级产物建立一次后复用；目标级产物每次重建 |
| **T4** | 幂等 + 状态机 | 每个阶段有 `pending / running / ok / failed / skipped` 五种状态 |
| **T5** | 版本演进与差分 | 同一目标的多个版本必须能对比差异 |
| **T6** | 时间旅行 | 分析状态可快照、可回滚（Ghidra `.rep/versioned/`） |
| **T7** | 分级时效 | 产物越不可复现，保留优先级越高 |

## 1.3 空间维度要求（S1–S8）

| 编号 | 要求 | 说明 |
| ------ | ------ | ------------------------------------- |
| **S1** | 稳定命名空间 | 用 [§3](../01-layout/02-目标标识.md) 的 target-id 定位；同一内容用 SHA256 内容寻址识别 |
| **S2** | 输入只读 | 容器挂载 `/target:ro` 与 `/output:rw` |
| **S3** | 分层存放 | 可丢弃的产物与必须保留的产物不得混放 |
| **S4** | 机器可读索引 | 索引描述目录树自身内容。参考 RO-Crate 的自描述思路 |
| **S5** | 大文件外置 | trace 与语料库文件常达 GB 级。参考 FACT 的建议：解包结果使用独立分区 |
| **S6** | 内容寻址去重 | 同一二进制只分析一次，其余位置用引用代替复制 |
| **S7** | 并发与原子写 | 先写临时文件，再执行原子改名 |
| **S8** | 隔离与合规 | 恶意样本物理隔离；权限 `700`、留存期限、交付前脱敏 |
