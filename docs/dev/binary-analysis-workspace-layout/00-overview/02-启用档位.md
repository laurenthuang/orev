# 14. 启用档位（D0–D2）

> 记号含义见 [§0](../00-overview/00-编号体系速查.md)。`D` = Depth，**数字越大越完整**。

| 档位 | 适用 | 必建 | 可选 |
| --------- | -------------------------- | ------------------------------------------------------------------------- | --------------------------------- |
| **D0 快速** | 半小时的小核查 | `CASE.md` + `00_inbox/{原始文件名,checksums.sha256,provenance.json}` + 用到的阶段 | `state/`、`60_diff`、`90_report` |
| **D1 标准** | 正式的单目标分析 | D0 + 全套阶段 + `state/index.jsonl` + `50_findings` | `investigation.jsonl` |
| **D2 完整** | 多目标 / 跨版本 / Agent 协作 / 长周期 | D1 + `investigation.jsonl` + `kb/` + `60_diff` + 封存清单 | `corpus/` |

> **D0 档位的唯一豁免项是 `stage.yaml`**。可以先不建立；**一旦需要复现或交付，必须回补**。豁免 `stage.yaml` 同时豁免了 [§16](../04-appendix/01-落地检查清单.md) 清单中的下列条目：「`tool.cmd` 可原样重跑」与「工具自检通过才可标记 `ok`」。
> **`provenance.json` 不在豁免范围内**，即使只填写来源与时间也要建立。它是 [§8.3](../03-operations/01-保留分级与清理.md#83-完整性校验) 完整性校验与 [§13](../03-operations/03-安全与隔离.md) 脱敏流程的输入。缺少该文件等于放弃溯源能力。

**档位升级的判断依据**：

- 一次分析中并行调查的问题超过 2 个时，启用 `investigation.jsonl`。
- 第 3 次遇到同类问题时，向 `kb/` 补写一篇文档。
- 手上有同一目标的第二个版本时，启用 `60_diff`。
