# 12. 结项封存（S4 落点）

本规范要求**结项时产出一份自述清单**。持有该清单的人在不联系分析者的前提下也能读懂整个案件。

```
90_report/                        # 案件级阶段，同样遵守 [§4.1](../01-layout/03-阶段目录契约.md#41-槽位结构任何阶段目录内只有这三样) 的三槽位
├── stage.yaml
├── out/
│   ├── manifest.json             # 自述清单（必需）
│   ├── report.md  report.html
│   ├── sbom.spdx.json
│   ├── evidence/F-003/           # 导出的证据包（[§6.5](../02-workflow/01-证据契约.md#65-证据导出吸收-reark-的-copy-evidence)）
│   └── poc/
└── log/
```

`manifest.json`：

样例见 [`schemas/manifest.json`](../schemas/manifest.json)。

**规则**：

- 封存后案件目录**只读**（执行 `chmod -R a-w`，或至少对 `00_inbox` 与 `50_findings` 设置）。
- `external_refs` 列出主树外的大文件及其校验和，保证封存包可完整取证。
- **冷区条目与工具区条目的 `path` 一律带 `<case-id>` 段**，例如 `store/router-2026q4/firmware/…/40_dynamic/out/trace.tar.zst`。`store/` 与 `tools/` 开头表示这是一条逻辑命名空间路径，物理位置由 `store_root` / `tools_root` 决定（[§2.1](../01-layout/01-顶层布局.md#21-冷区-store-与工具资产区-tools)）。带 `<case-id>` 段的理由不是冗余：实体脱离主树后就失去了上下文，路径必须自解释。结项时按该前缀即可筛选出本案件需要带走的全部外部资产。
- **工具工作区条目必须标注 `kind: "tool-project"`，并写明工具名与版本**。这类条目不是普通文件，没有单一哈希，且数据库格式随工具版本变化。只记录路径等于没有记录。结项时必须带走 `tools/<tool>/working/<case-id>/` 下本案件的整棵子树。[§2.1](../01-layout/01-顶层布局.md#21-冷区-store-与工具资产区-tools) 要求工具区镜像主树结构，目的就是让这一步能整块切走。
- 对外交付需要完整 RO-Crate 时，从 `manifest.json` 生成 `ro-crate-metadata.json` 即可。两者字段一一对应。
