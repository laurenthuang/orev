# 10. 知识库与语料库

`kb/` 与 `corpus/` 都跨案件复用。区别在于**前者供人阅读，后者供机器消费**：

| | `kb/` | `corpus/` |
| --- | ----------------------- | ------------------------------ |
| 内容 | 技法、踩坑记录、可复用规则 | 签名库、参考二进制集、特征数据库 |
| 消费者 | 人 / Agent 读文本 | 工具直接加载 |
| 例子 | `unpack-upx-variant.md` | FLIRT 签名、**BSim 数据库**、libc 参考集 |
| 必要性 | **推荐** | **可选**（单人场景价值有限，仅 D2 启用） |

```
kb/
├── techniques/      # 通用技法
├── signatures/      # YARA 规则、常量指纹表
└── pitfalls/        # 踩坑记录
corpus/
├── flirt/           # 库函数签名（Ghidra FLIRT / rizin rz-sign / IDA F.L.I.R.T. 通用）
├── reference-bins/  # 参考二进制集（用于相似度比对）
├── bsim/            # Ghidra BSim 数据库（H2 / PostgreSQL）
└── feature-db/      # 特征数据库
```

> **BSim 的归属容易混淆，此处明确切分**：
>
> - **数据库本体归入 `corpus/bsim/`**。该类数据跨案件复用，一次建立并长期积累。三种后端任选其一：H2（本地零安装，单人场景首选）、PostgreSQL（生产环境首选）、Elasticsearch（集群部署）。
> - **单次生成的签名与查询结果归入案件内** `30_decompile/out/`，文件为 `signatures.xml` 与 `bsim-matches.csv`。这些内容针对某个具体目标，不属于语料库资产。
> - **必须记录构建命令**。BSim 数据库依赖模板（如 `large_32`，约 1 亿函数规模）与 Ghidra 版本。**更换 Ghidra 版本后签名不可比**。在 `corpus/bsim/README.md` 中记录创建命令与版本，否则半年后该库无法使用。
> - 生产部署需要 SSL。PostgreSQL 后端需要自行构建（使用 `make-postgres.sh`），官方未提供预编译包。

**`kb/` 每篇文档使用固定结构**（参考 open-reverselab 的可执行知识库原则：无法执行的内容不收入知识库）：

模板见 [`schemas/kb-article-template.md`](../schemas/kb-article-template.md)。

**纪律**：`kb/` 每篇文档必须来自真实案件，并回链到该案件。`corpus/` 每个条目必须记录来源与构建命令。缺少这些记录时，半年后无人知道该签名库的来源。
