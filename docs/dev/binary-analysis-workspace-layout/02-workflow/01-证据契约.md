# 6. 证据契约 `findings.jsonl`

> 本节是本规范的核心。每条结论必须携带可复核的证据链。人工分析时，证据链提升结论可信度。由 Agent 产出结论时，证据链是强制要求，否则幻觉会混入结论。

## 6.1 Schema

样例见 [`schemas/findings.jsonl`](../schemas/findings.jsonl)。每行一个 JSON 对象，字段约束见 [§6.2](#62-字段约束)。

要点：每条 evidence 必须同时具备三项内容：`path`、定位信息（`offset` / `line` / `symbol` 之一）、`sha256`。缺少定位信息的证据无法复核。

## 6.2 字段约束

| 字段 | 必填 | 规则 |
| ------------------ | -- | ------------------------------------------------------------------------- |
| `claim_id` | ✅ | `F-<三位>`，一旦分配永不复用 |
| `status` | ✅ | `confirmed` / `inferred` / `assumed` / `refuted` |
| `confidence` | ✅ | 0–1，**必须落在 [§6.3](#63-evidencetype-受控词表吸收-reark) 的区间内** |
| `evidence[]` | ✅ | **至少一条**。每条必带 `path`（相对案件根）+ 定位信息（`offset`/`line`/`symbol`）+ `sha256` |
| `evidence[].type` | ✅ | **受控词表**，见下表 |
| `limitations` | ✅ | 不可为空。**缺少局限说明，视为未完成分析** |
| `unknowns[]` | ✅ | 可为空数组，但字段必须存在。用于记录尚未查明的问题 |
| `evidence[].query` | ⬜ | **可复现的查询参数**。证据由查询得出，不是凭记录得出。记录参数才能重新查询 |
| `corroboration` | ⬜ | 说明为何是这个 `status` |
| `thread` | ⬜ | 纵轴关联，见 [§7](../02-workflow/02-调查线索.md) |

## 6.3 `evidence[].type` 受控词表（吸收 ReArk）

| type | 含义 | 典型定位方式 |
| ------------- | ------------------------- | --------------------- |
| `header` | 文件头 / 节表 / 加载命令 | `offset` / `field` |
| `disassembly` | 汇编指令 | `offset` |
| `decompiled` | 反编译伪代码 | `offset` / `function` |
| `literal` | 常量与字面量 | `offset` / `value` |
| `string` | 字符串 | `offset` / `line` |
| `xref` | 交叉引用 | `symbol` / `offset` |
| `flow` | 数据流 / 调用参数流 | `function` |
| `tree` | 结构树（包体、类、模块） | `node_path` |
| `hash` | 哈希常量（SHA/MD5/AES S-box 等） | `offset` / `value` |
| `base64` | 内嵌编码数据 | `offset` |
| `signature` | 签名、证书链 | `field` |
| `trace` | 运行时轨迹 / 系统调用 / 网络 | `seq` / `timestamp` |

> 前七类取自 ReArk ABC Evidence Workspace 的视图划分（Tree / Literal / Strings / XRefs / Flows / Hashes / Base64）。后五类为覆盖原生与动态场景所补充。

## 6.4 `status` 与 `confidence` 的区间约束

同时使用两套置信度表达容易产生矛盾，例如 `status: assumed` 配 `confidence: 0.9`。本规范建立确定性映射：

| status | confidence 区间 | 判定条件 |
| ----------- | ------------- | ------------------------------------------------------- |
| `confirmed` | `> 0.8` | **两个及以上独立证据源一致**（如反汇编出 AES S-box **且** 字符串里有 `AES-256`） |
| `inferred` | `0.5 – 0.8` | 单一权威证据源（`file` 输出、字符串、未 strip 的符号名、托管代码反编译） |
| `assumed` | `≤ 0.5` | 无直接证据的推断（stripped 原生反汇编的控制流解读、数据结构重建、意图归因） |
| `refuted` | 任意 | 已被证据推翻，**保留记录不删除**（避免重复分析） |

校验脚本必须拒绝区间外的组合。**默认纪律：原生二进制分析的默认档位是 `assumed`**。二进制分析具有解释性，对不确定性必须诚实。

## 6.5 证据导出（吸收 ReArk 的 `Copy Evidence`）

证据必须支持一键导出，用于输入 Agent、写入报告或交由他人复核。

导出命令见 [`scripts/export-evidence.sh`](../scripts/export-evidence.sh)。

产出：

```
90_report/out/evidence/F-003/
├── finding.json          # 该条结论（含 evidence[]）
├── refs/                 # 引用文件的副本（保持原相对路径）
│   └── firmware/archerc7v5_up_201229_a1b2c3d4e5f6/30_decompile/out/usr_sbin_httpd/decompiled.c
└── checksums.sha256      # 全部副本的校验和
```

**规则**：副本只读；副本带校验和；`refs/` 内保持原始相对路径。持有证据包的人无需访问原项目即可完成复核。
