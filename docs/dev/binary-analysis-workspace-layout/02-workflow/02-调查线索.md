# 7. 纵轴：调查线索 `state/investigation.jsonl`

样例见 [`schemas/investigation.jsonl`](../schemas/investigation.jsonl)。每行一个 JSON 对象，不换行展开。

| 字段 | 说明 |
| ---------------- | --------------------------------------------- |
| `thread_id` | `TH<序号>`，与产物 `tags` 中的 `thread=TH2` 对应 |
| `question` | 本线索要回答的具体问题。**写不出具体问题，说明不值得开设线索** |
| `status` | `active` / `blocked` / `done` / `abandoned` |
| `next_actions[]` | **下一步动作**。用于断点续做，隔周回来无需重新回忆 |
| `dead_ends[]` | **已排除的路径**。逆向工作多数时间消耗在走不通的路径上，而人工记忆与 Agent 上下文都会丢失 |
| `claim_refs[]` | 关联的 `claim_id` |
| `blocked_by` | 被什么阻塞 |

> **双向关联的写入方向**：`findings.thread` 是**写入源**，`investigation.claim_refs` 是**派生的反向索引**，可由脚本重建。不要在两处手工维护，以免产生不一致。

## 查询

三条查询见 [`scripts/query-investigation.sh`](../scripts/query-investigation.sh)：按目标横向查、按线索纵向查、重建线索到结论的反向索引。
