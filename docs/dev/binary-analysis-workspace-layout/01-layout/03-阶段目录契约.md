# 4. 阶段目录契约

## 4.1 槽位结构（任何阶段目录内只有这三样）

```
<NN>_<stage>/
├── stage.yaml      # 状态机 + 溯源（T2/T4），含 inputs / outputs
├── out/            # 产物；多组件时按 <slug>/ 分桶（[§3.3](../01-layout/02-目标标识.md#33-固件内部组件)）
└── log/            # run.log / run.err / metrics.json
```

> **阶段目录中没有 `in/` 槽位**。输入引用写在 `stage.yaml` 的 `inputs` 字段中，包含 `path` 与 `sha256`（[§4.3](#43-stageyaml-字段定义)）。`in/` 目录没有消费者：存符号链接违反 [§8.1.1](../03-operations/01-保留分级与清理.md#811-required-备份纪律) 第 5 条；存引用清单会与 `inputs` 字段重复并必然漂移；留空则是空目录。

> **槽位名一律不加 `_` 前缀**。早期版本使用 `_stage.yaml`，本意是标记「控制文件而非产物」。经实测后放弃该写法。理由如下，前两条为实测结论：
>
> 1. **排序收益不确定**。该收益依赖 locale，且方向会反转：`LC_COLLATE=C` 下 `_`（0x5F）排在小写字母之前；默认 UTF-8 locale 下排在最后（glibc collation 忽略标点，按 `stage.yaml` 参与排序）。收益不确定的方案不算收益。
> 2. **不提供 glob 隐藏**。`for f in *` 仍会命中下划线开头的文件。只有 `.` 前缀具备该效果。认为加了 `_` 就不会被遍历脚本读取属于常见误解。
> 3. **语义已经足够**。「这不是产物」由两点表达：文件名 `stage` 本身；文件位于**阶段根目录**而非 `out/`。下划线是冗余的第二重标记，且需要额外规定「只允许一个下划线文件、禁止扩展 `_xxx`」。规则越少越好。
>
> ⚠️ **遍历脚本必须显式排除 `stage.yaml`**（例如扫描产物时用 `fd` 加 `-E stage.yaml`），**不能依赖前缀**。另注意：部分工具链（Jekyll 等静态站点生成器）会**静默忽略** `_` 开头的文件 —— 这是放弃前缀的附带收益。

## 4.2 阶段编号

| 编号             | 阶段             | 说明                           |
| -------------- | -------------- | ---------------------------- |
| `00_inbox`     | 获取与确权          | 原始输入、来源、哈希、授权                |
| `10_unpack`    | 解包 / 脱壳 / 组件枚举 | 提取出原始内容                      |
| `15_patch`     | 修改版样本          | 脱壳结果、补丁、重建二进制、**重签名包**；原件永不动 |
| `20_static`    | 静态提取与清单化       | 头、节、符号、字符串、导入导出、SBOM         |
| `30_decompile` | 结构恢复           | 反汇编、反编译、CFG、工具项目数据库          |
| `40_dynamic`   | 动态与深度分析        | 仿真、符号执行、污点、Fuzzing、真机交互      |
| `50_findings`  | 研判与定级          | 证据契约、去重、定级、交叉验证              |
| **`60_diff`**  | **跨版本对比**      | **案件级**，比较两个 target-id 的差异   |
| `90_report`    | 案件级交付          | 报告、SBOM、PoC、封存清单             |

当前 PoC 在读取配置时严格校验 `stages`：仅接受上表九个完整名称，区分大小写且不自动裁剪空白；未知名称或空字符串会明确报错，`init` 与 `doctor` 以失败退出，且不因该配置新增工作区资源。允许空列表 `[]`，本校验不检查执行依赖或阶段完成状态，也不执行分析。

> **跳过的阶段不再强制建立占位目录**。启用列表由 `orev.toml` 的 `stages` 声明。单人场景下，为不执行的阶段建立空目录属于额外负担。
>
> **`60_diff` 与 `90_report` 属于案件级阶段**，位于案件根目录，不在单个目标目录内。差异分析与报告都天然跨多个目标。

启用列表与差异任务在 `orev.toml` 中声明。扩展设计参考见 [`schemas/orev.toml`](../schemas/orev.toml)，其中 `[[diff]]` 与 `[sample]` 尚未在当前 PoC 实现，配置这些字段会被拒绝。要点：

- `stages` 声明本次实际执行的阶段。未声明的阶段不建目录。
- `[[diff]]` 声明 `60_diff` 的两端 target-id 与所用工具，并用 `name` 给这一组命名。该表可重复出现，**一组一次对比**。
- `name` 同时决定产物目录名：`60_diff/out/<name>/` 与 `tools/ghidra/working/<case-id>/ghidra-vt/<name>/`。取值必须案件内唯一，且能读作「从什么到什么」（例：`124-to-125`）。**不要写 target-id 全名**，那会得到一个 60 字符以上的目录名。
- `[sample]` 的 `retention_days` 声明恶意样本的保留天数。

## 4.3 `stage.yaml` 字段定义

完整字段定义见 [`schemas/stage.yaml`](../schemas/stage.yaml)。要点：

- `status` 取值 `pending` / `running` / `ok` / `failed` / `skipped`。判据是 `tool.selfcheck`，不是退出码。
- `tool.cmd` 使用绝对路径。命令中的 `$TOOLS_ROOT`、`$TARGET`、`$TARGET_INPUT` 由 runner 在运行前展开。
- `$TARGET_INPUT` 指向 `00_inbox` 内的主输入，取值来自同文件的 `input_file`（[§5.2](../01-layout/04-阶段产物清单.md#52-00_inbox-两个元数据文件的职责边界)）。原始文件名不固定，命令中禁止写死文件名。
- `tool.project_dir` 相对 `tools_root`，取值为 `tools/<tool>/working/<case-id>/` 之后的部分。工具名前缀不在其中重复。
- `tool.selfcheck` 任一项为 `false`，或 `timeout_truncated` 为 `true` 时，`status` 不得为 `ok`。
- `tool.signing_material` 仅 `15_patch` 阶段使用。只记路径与指纹，不记密钥。
- `inputs` 引用而非复制，每条必带 `sha256`。`outputs` 每条必带 `retention` 与 `tags`。

> **所有 `path` 字段的路径基准统一为案件根目录。** 早期版本使用相对 `stage.yaml` 的路径，导致 `50_findings` 引用 `30_decompile` 时写成 `../30_decompile`（层数不足，正确写法为 `../../`）。多层相对路径不可维护。统一基准后，脚本与人工都不会算错层数。

## 4.4 环境快照 `state/env.md`

手工记录工具版本容易过期。本规范改用**自动探测加 TTL 缓存**（参考 open-reverselab 的环境快照协议）：

格式样例见 [`schemas/env-snapshot.md`](../schemas/env-snapshot.md)。要点：

- 文件记录 `generated_at` 与 `protocol_version`。
- 超过 `ttl_days`（默认 7），或 `protocol_version` 变更后重新探测。
- 敏感环境变量只记 `SET`，不记取值。

规则：超过 `ttl_days`（默认 7）或 `protocol_version` 变更后重新探测；敏感变量只记 `SET`；**此文件永不进 git**。

> `env.md` 的保留级别为 temp，可以删除。删除前必须确认各 `stage.yaml` 的 `env_fingerprint` 已写入字段。指纹存在，环境就可复现。
